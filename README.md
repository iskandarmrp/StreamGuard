# StreamGuard: Indonesian Live Stream Donation Moderation System

StreamGuard is a content moderation system that automatically detects **toxic language** and **online gambling promotion (judi online)** in Indonesian live stream donation messages. The project covers the full pipeline: chat scraping, hybrid LLM/manual labeling, a staged preprocessing study, transformer fine-tuning, and a working full-stack prototype that gates donations in real time.

---

## ⚠️ Data & Content Policy

This is the **public research release**, and it is deliberately conservative.

The working repository contains raw scraped live chat: gambling promotion written verbatim by spammers, abusive messages, and the YouTube handles of the people who sent them. None of that is republished here, in any form.

**The rule applied to this repository:** notebook outputs may contain aggregate numbers and metrics only. No user-generated text survives anywhere in this release.

Concretely, the following were removed from every notebook:

| Removed | Why |
| :-- | :-- |
| Raw message rows, `.head()` previews, rendered data tables | Republishes user content verbatim |
| Confusion-matrix breakdowns listing individual messages | Republishes the text *and* attaches a public verdict to it |
| Word and n-gram frequency listings | These are user vocabulary, including slurs |
| Charts plotting top words or top usernames as labels | Same content, rendered as pixels |
| Gambling site names | Promotional material for illegal services |
| YouTube handles | Personal data, and no analytical value for text classification |
| Styled-Unicode sequences | Filter-evasion glyphs used by spammers |
| Local filesystem paths in warning traces | Leaks the author's machine layout |

What remains: dataset sizes, label distributions, classification reports, confusion matrix figures, training logs, and the full source code of every step.

Derived lexicons are not redistributed either. `resources/` ships only the stopword list; the merged slang dictionary is rebuilt from its two public sources by `preprocessing/stopwords_and_kamus_alay_preparation.ipynb`, and the corpus frequency lists that feed `symspellpy` are regenerated by `preprocessing/count_words.ipynb`.

Because the removal rule is applied at whole-output granularity, a few benign outputs went with it — notably `df.info()` schema dumps, which were dropped for naming a `Username` column. The dataset schema and label counts are documented below instead.

The full labeled dataset and trained model weights are **available to researchers on reasonable request**.

## 🚀 Features

- **Toxicity Detection** — abusive, insulting, and inappropriate language, tuned to Indonesian live stream register.
- **Online Gambling Promotion Detection** — direct and obfuscated promotion of illegal gambling networks.
- **Hybrid Preprocessing Pipeline** — token normalization, slang/abbreviation mapping, and spell correction, evaluated as independent variables.
- **Full-Stack Prototype** — Next.js dashboard with authentication, plus a FastAPI inference service that scores every donation message before payment.

## 🧹 Preprocessing Pipeline

Live stream chat is short, noisy, and heavily abbreviated, so preprocessing is treated as an experimental variable rather than a fixed step.

### Mandatory (all models)

- Emoji removal
- URL removal
- Lowercasing
- Character repetition capped at 3 characters
- Whitespace trimming

### Experimental (ablated per model)

- **Slang normalization** via dual Indonesian slang lexicons
- **Typo correction** via `symspellpy` over an Indonesian web corpus
- **Shallow baselines only** — stopword removal and `PySastrawi` stemming

## 📊 Dataset & Evaluation

Gambling promotion is rare in any single stream, so the corpus combines scraped live chat with external Kaggle datasets.

**Schema** — `Waktu` (timestamp), `Pesan` (message), `Pesan_Clean` (preprocessed), `Label Toxic`, `Label Judi Online`. The sender identity column present in the working data is dropped from any release.

**Scale** — 80,437 messages total; 3,875 labeled toxic and 4,234 labeled gambling promotion. Both target classes sit near 5% prevalence, which is why macro-averaged metrics are the only meaningful summary.

Data is split **by YouTube channel**, not randomly. Random splitting would leak channel-specific vocabulary and spammer templates across folds and inflate results; splitting by channel measures what actually matters — cross-channel robustness on unseen communities.

## 🔍 Error Analysis

**1. Toxicity is bounded by annotation subjectivity.** The model plateaus below 0.90 F1 largely because the task itself is underdetermined. Many Indonesian slang intensifiers are descriptive in gaming contexts and insulting elsewhere, with no disambiguating signal in a five-word message. Sarcasm and superficially polite phrasing pass through.

**2. Gambling detection fails in both directions, for different reasons.** Ordinary gaming vocabulary that slot communities have co-opted drives false positives, since the same words describe high performance in entirely innocent contexts. False negatives come from deliberate character obfuscation, where spammers substitute mathematical Unicode glyphs and insert spacing to break tokenization.

**3. The gambling failure is inherited, not learned.** Recall consistently exceeding precision across every configuration points at the training labels rather than the architecture: `gpt-5.4-mini` itself failed to catch the obfuscated spam it was asked to label, so the model never saw those patterns marked positive. This is the central limitation of silver-standard labeling for adversarial tasks — the student cannot exceed a teacher that is blind to the hardest cases. Fixing the gambling detector means fixing the labels first.

## ⚖️ Intended Use

This work is intended for content moderation research and for building protective tooling for streamers. It is not intended for, and the published artifacts do not support, promoting gambling services, profiling or targeting individual users, or automated punitive action without human review — the gambling classifier's 0.30 F1 makes it unfit for unsupervised enforcement.
